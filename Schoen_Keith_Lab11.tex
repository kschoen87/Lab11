\subsection{Analyzing the Execution Timeline}
\subsubsection{Process Activity}
\begin{itemize}
	\item The application launches itself via .exe file
	\item The initial application launches multiple child processes (exe.exe (\#XWORM), schtasks.exe, and conhost.exe)
	\item Injected into explorer.exe, svchost.exe, and system32.exe
	\item For each process needed to gather information to send back the the C2, exe.exe runs schtasks.exe to run legitimate
	windows applications (such as PDF FILE PREVIEWER) for future tasks.
\end{itemize}
\subsubsection{File System Activity}
\begin{itemize}
	\item This malware did not create any new files.
	\item Five executables were dropped
	\begin{itemize}
		\item \texttt{\scriptsize{C:\textbackslash Users\textbackslash admin\textbackslash AppData\textbackslash Local\textbackslash Temp\textbackslash p3zwhafveql.ps1}}
		\item \texttt{\scriptsize{C:\textbackslash Users\textbackslash admin\textbackslash AppData\textbackslash Roaming\textbackslash system32.exe}}
		\item \texttt{\scriptsize{C:\textbackslash Users\textbackslash admin\textbackslash AppData\textbackslash Roaming\textbackslash Microsoft\textbackslash Windows\textbackslash Start Menu\textbackslash Programs\textbackslash Startup\textbackslash system32.lnk}}
		\item \texttt{\scriptsize{C:\textbackslash Users\textbackslash admin\textbackslash AppData\textbackslash Roaming\textbackslash Microsoft\textbackslash Windows\textbackslash Start Menu\textbackslash Programs\textbackslash Startup\textbackslash ivrbDjKYgQZkne.lnk}}
		\item \texttt{\scriptsize{C:\textbackslash Users\textbackslash admin\textbackslash AppData\textbackslash Roaming\textbackslash ivrbDjKYgQZkne.exe}}
	\end{itemize}
	\item Rewrote \texttt{C:\textbackslash Users\textbackslash admin\textbackslash AppData\textbackslash Roaming\textbackslash system32.exe}
	\item There were no \textbf{delete events}.
\end{itemize}
\subsubsection{Registry Activity}
There was one modification event that showed evidence of persistence:
\begin{itemize}
	\item \scriptsize{\textbf{{PID} Process:} (6856) exe.exe}
	\item \scriptsize{\textbf{Operation:} Write}

\vspace{1em}
\noindent\textbf{Summary:} Every malicious behavior observed in this XWorm sample maps
directly to at least one tool from L24. The most powerful combination is
\textbf{Autoruns} (catching all three persistence mechanisms simultaneously) paired
with \textbf{Sysmon} (providing full forensic provenance for each event). TCPView and
Sysmon Event ID 3 together provide host-side attribution of the C2 beacon that
tcpdump alone --- which sees the traffic but not the responsible process --- cannot
supply.
\subsection{Map to MITRE ATT\&CK}
\textbf{Scheduled Task/Job (T1053) - Execution}
\begin{itemize}
	\item The malware alters scheduled tasks for recursive calls to establish persistence.
	\item In the case of XWORM, it regersters and creates system tasks to activate background processes and establish a connection to the C2 server.
\end{itemize}
\textbf{Registry Run Keys/Startup Folder (T1060) - Persistence}
\begin{itemize}
	\item The malware add at program to the startup folder or referencing it with a Register Key therefore causing the malware to be 
	executed whenever the user logs in.
	\item XWORM attempted to set its autorun on the system startup.
	\item This strategy belongs in the Persistance column.
\end{itemize}
\textbf{Hooking (T1179) - Privilege Escalation}
\begin{itemize}
	\item The malware uses Windows built-in API functions to implant code in ordinary processes to be executed across platforms to potentially
	elevate privileges.
	\item XWORM used this function as a sort of keylogger.
\end{itemize}
\textbf{Reflective Code Loading (T1620) - Stealth}
\begin{itemize}
	\item Malicious code is loaded directly into process memory, disguising it as it moves through the system, executing when it reaches its target.
	\item XWORM invokes .NET assembly method \begin{verifybox} \begin{center}\texttt{api: System.Reflection.ConstructorInfo::Invoke}\end{center} \end{verifybox}
\end{itemize}
